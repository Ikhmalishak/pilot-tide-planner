# 1. Product Overview

## Introduction

TideNav is a web-based navigation decision support system designed for marine operators to determine suitable navigation periods based on tide information.

Currently, marine operators manually compare:

1. Tide indicator tables containing HIGH and LOW tide events.
2. Hourly tide level tables containing hourly water levels.

Operators then manually highlight suitable navigation periods.

This process is time-consuming and dependent on human calculation.

TideNav automates this process by applying configurable navigation rules through a dedicated Navigation Engine.

---

# 2. Problem Statement

Marine operations require accurate understanding of water conditions before navigation.

The current workflow:

```
Receive tide data

↓

Manually compare tide indicators

↓

Calculate threshold levels

↓

Check hourly tide levels

↓

Highlight suitable hours

↓

Prepare navigation schedule
```

Problems:

- Manual calculations take time.
- Different operators may produce different results.
- Rule changes require manual recalculation.
- Historical records are difficult to maintain.

---

# 3. Product Objective

TideNav aims to:

# 5. Core Concepts

The system consists of three primary data sources.

---

# 5.1 Tide Indicators

Tide indicators represent important tidal events.

Examples:

- HIGH tide
- LOW tide

Example:

| Date | Time | Type | Level |
|------|------|------|-------|
|01 July 2026|01:47|HIGH|7.22 ft|
|01 July 2026|07:53|LOW|3.61 ft|
|01 July 2026|13:45|HIGH|8.86 ft|

---

# 5.2 Hourly Tide Levels

Hourly tide levels represent water conditions throughout the day.

Example:

| Date | Time | Level |
|-|-|-|
|01 July 2026|01:00|7.20 ft|
|01 July 2026|02:00|7.10 ft|
|01 July 2026|03:00|6.80 ft|

---

# 5.3 Navigation Window

Navigation Window is the final output generated by the Navigation Engine.

Example:

| Time | Status |
|-|-|
|01:00|RED|
|02:00|RED|
|03:00|YELLOW|
|04:00|GREEN|

The Navigation Window represents the recommended operational condition for each hour.

# 8. Functional Requirements

---

## FR-001: Manage Tide Indicators

The system shall allow users to:

- Create tide indicators.
- Update tide indicators.
- Delete tide indicators.
- Import tide indicators.

---

## FR-002: Manage Hourly Tide Levels

The system shall allow users to:

- Create hourly readings.
- Update hourly readings.
- Delete hourly readings.
- Import hourly readings.

---

## FR-003: Generate Navigation Window

The system shall:

1. Validate tide data.
2. Load active Rule Profile.
3. Execute Navigation Engine.
4. Generate hourly navigation status.
5. Store generated result.

---

## FR-004: View Navigation Window

Users shall be able to:

- View today's navigation window.
- View historical navigation windows.
- Filter by date.

---

## FR-005: Manage Rule Profiles

Administrators shall be able to configure:

- Red threshold.
- Yellow threshold.
- Green threshold.
- Time restrictions.

---

# 9. Non Functional Requirements

## Performance

The system should generate one day's navigation window within one second.

---

## Reliability

The system must validate all input data before processing.

---

## Maintainability

Business rules must exist only inside the Navigation Engine.

---

## Scalability

The system should support:

- Multiple locations.
- Multiple rule profiles.
- Future API integrations.

# 13. Success Criteria

TideNav is successful when:

- Operators no longer manually calculate navigation periods.
- Generated results match existing manual calculations.
- Rule changes can be applied without code modification.
- Historical navigation windows can be reviewed.
- New data sources can be added without changing the Navigation Engine.

---

# 14. Design Principles

## Principle 1

The Navigation Engine owns all calculations.

---

## Principle 2

The database stores raw tide data and generated outputs separately.

---

## Principle 3

Frontend components only display information.

---

## Principle 4

Backend controllers coordinate requests only.

---

## Principle 5

All input sources must produce identical domain objects.

---

## Principle 6

Business rules must be configurable.
